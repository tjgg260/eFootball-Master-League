# Database Blueprint — the compiled world

Decided 2026-08-24 with the owner. `master.db` is a **compiled artifact**: raw sources in the repo
are inputs, one deterministic pipeline builds the world, and a validation gate fails the build if
the output is broken. The database is disposable output — rebuild, don't surgically patch.

## Entities

Players, Teams, Leagues, Competitions (cups/continental/pyramid links), Staff, Stadiums, Kits,
Rivalries, National teams.

## The identity spine

Every entity is matched across sources ONCE, persisted, and reviewable — all later joins are exact:

```
player_identity(player_id, ef_pid, fm_uid, rfs_pid, kind, confidence, method)
team_identity  (team_id, ef_team_id, fm_club_id, rfs_team_id, sportsdb_id, footballdata_id,
                confidence, method)
```

FM UID is the ecosystem's universal key: sortitoutsi faces, DVX logos, Genie market/staff/clubs
are all FM-keyed. The only hard join is eFootball↔FM (name+dob+nationality, unique-guarded);
low-confidence pairs go to a review CSV, never silently merged. Career copies (20M–700M) and the
curated overlay (45B) are ephemeral render material and stay OUT of the spine.

## Source priority — per FIELD, owner-decided

| Field group | 1st | 2nd | 3rd |
|---|---|---|---|
| Club membership (who plays where) | **FM (latest export)** | eFootball | RFS |
| League structure & league membership | **internet APIs** (football-data > TheSportsDB) | **RFS** (deep pyramid) | FM |
| Player names | **eFootball (licensed)** | **FM (real names)** | RFS only if in neither |
| Attributes / skills / playstyles / appearance (real players) | **eFootball native** | FM-converted (S-curve) | synthesized |
| Potential / personality / determination | FM | derived | — |
| Value / wage / contract | FM Genie (cap+zero repaired) | formula | — |
| Faces | sortitoutsi by fm_uid | Uran generated by nationality | disc |
| Logos | **DVX packs (in repo, fm_club_id-keyed)** | API crests | RFS |

Every merged field carries provenance (`source` tag).

## Hard rules

1. FM is the truth for WHERE players play (refreshable: new FM export → keyed diff → apply).
2. Every player has attributes/skills expressible in eFootball, plus sim-only extras
   (personality, determination, potential, market data).
3. eFootball is the truth for real players' attributes, appearance and skills.
4. Real faces + real logos for as many players/teams/leagues as possible; generated fallbacks
   for the rest — nobody faceless, no club without a badge.
5. Every team ≥ 18 players including ≥ 2 GKs (generated fillers, nationality-correct names).
6. **Writable to eFootball on launch**: every team must pass a dry-run of the writeback
   projection — squads fit the PlayerAssignment slot model, attributes within template ranges,
   playstyles map to valid STYLE_INDEX values, names encode safely. The build FAILS if any
   catalog team cannot be rendered into the game.

## World-edge policy (who lives outside your divisions)

The career's two divisions + their U21/U18 sides + the academy get the FULL simulation
(personality-driven development, condition, economy). Everyone else in the world gets the
**edge treatment** once per season at rollover (`Session.AgeWorldEdge`): every squad player ages
a year; under-24s drift up toward (never past) their stored potential, 31+ decline, 35+ decline
faster; at 39 they retire out of their squad into the free-agent pool (records kept — nothing is
ever deleted). Deterministic per (player, season) — cheap SQL, no RNG loops. The world is no
longer immortal: leave for five seasons and come back to a changed one.

## Validation gate (audit-as-build-step)

Zero dangling references · one squad membership per player · every squad player fully attributed
· ≥18+2GK per team · no duplicate identity inside a squad · repo-relative paths only · id
namespaces respected (eF <16.7M · career 20M–700M · RFS 700M–10B · FM 10–13B · curated 45–46B ·
generated ≥50B) · every catalog club has logo + league + country · render-projection dry-run OK.

## Build order

ingest → resolve identities → merge by priority → derive (gap synth, fillers, youth split by
age/ability, staff placement, stadiums, kits, rivalries) → validate → emit.
